## 1. Discover unique keys

- [ ] 1.1 Extend `RELEVANT_OPERATION_TYPES` and the routing in `src/mongo_client_cache/_core/stream_events.py` to include `createIndexes`/`dropIndexes`, since the stream's `$match` stage currently excludes both regardless of `show_expanded_events=True`; verify a `createIndexes`/`dropIndexes` event on a live collection now reaches the router instead of being filtered out server-side.
- [ ] 1.2 Add a per-`CacheManager` collection-metadata cache keyed by namespace, tracking a dedicated per-namespace index generation that advances on a routed `createIndexes`/`dropIndexes` event for that namespace or on a namespace epoch advance, that calls `list_indexes()` on first use and re-verifies whenever the index generation has advanced since the last check; filter to indexes with `unique: true`, no `partialFilterExpression`, not `sparse`, and not hashed, extracting field order and collation; verify discovery happens once and is shared across handles, that excluded index shapes are never used, and that an in-place `createIndex`/`dropIndex` is detected once its change-stream event has been processed.

## 2. Cache unique-key reads

- [ ] 2.1 Add unique-key identity caching that matches a read's filter and effective collation against discovered keys, captures only the namespace generation for an unresolved alias or a negative result (keyed by unique-key definition, value, and read shape), ensures `_id` is present in the server-side projection whenever an alias might need resolving — overriding `_id: 0` to `_id: 1` only for an inclusion-style caller projection, omitting the caller's `_id: 0` instead for an exclusion-style one — strips it from the returned/cached value if the caller excluded it, and on a match resolves the alias and admits an identity-guarded entry for the matched document alongside the namespace-guarded one, per `design.md`; verify an independent raw client drives invalidation for both resolved and unresolved cases, that a unique-key match with an inclusion-style projection excluding `_id` still resolves its alias without leaking `_id`, that a unique-key match with an exclusion-style projection excluding `_id` does the same without ever sending an invalid mixed projection to the server, and that a first-time match's alias survives (a subsequent read of the same key value takes the identity-guarded path) rather than being pruned immediately.
- [ ] 2.2 Add cache-miss handling for a resolved unique-key alias that queries by the caller's original predicate rather than the resolved identity, compares the response's identity against the alias's recorded one, and on a mismatch (or no match) discards/re-resolves the alias and admits the result as an unresolved read would, per `design.md`; verify that a write changing the aliased document's key field is not masked by a query that would otherwise trust the stale identity, that a namespace drop-and-recreate reusing the same `_id` for a different document does not leak that document under the old key's alias, and that a still-accurate alias correctly refreshes its identity-guarded entry without unnecessary re-resolution overhead beyond the one extra round trip a miss already pays.
