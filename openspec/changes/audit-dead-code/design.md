# Design

## Context

See [proposal.md](proposal.md). Two independent audit techniques are needed because the two dead-code shapes have different signatures:

- **Test-only symbols**: a `src/` function or method that only appears in `tests/` text, never called from another `src/` module. Static cross-reference (definitions vs. call sites, excluding `tests/`) finds these without running anything. Confirmed: `CacheCore.lifecycle_state` and `CacheCore.lookup_by_alias` in `src/client_query_cache/_core/manager.py` — production code calls `resolve_alias` + `lookup_identity` separately instead of the combined `lookup_by_alias`, and nothing reads `lifecycle_state` outside `tests/core/test_lifecycle.py`, `tests/asynchronous/test_manager.py`, and `tests/synchronous/test_manager.py` (all `pytest.mark.unit`).
- **Always-true/always-false branches on driver-sourced values**: a conditional in `src/` that guards on the shape of a value MongoDB or pymongo actually produced (change-stream events, `wallTime`, index specs, driver return objects) — as opposed to a conditional over caller-supplied input (filters, projections, collations), which legitimately varies and is not in scope. These are confirmed dynamically: temporarily replace the guard with an `assert` of the branch the code currently treats as the common case, run the non-unit suites (`just test-integration`, `just test-e2e`, and `uv run -- pytest tests/benchmark`) with real MongoDB via `testcontainers`, and if they pass, delete the alternate branch and the temporary `assert` together — the `assert` is a local diagnostic only and is never committed. Confirmed: `_wall_time_seconds` in `src/client_query_cache/_core/stream_events.py` — asserting `value.tzinfo is None` and dropping the `replace(tzinfo=...)` branch only fails 3 tests in `tests/benchmark/stream_cost/test_guard_workload_integration.py` that construct a tz-aware `datetime` by hand; the full integration and e2e suites, which only ever see real change-stream `wallTime` values, are unaffected.
- **Dead fallback keys on driver-sourced mappings**: a `mapping.get(key, default)` call where `mapping` comes from a MongoDB/driver response (e.g., `list_indexes()` index specs, `listCollections` entries) and `key` is expected to almost always be present. `.get()` with a default gives no coverage signal about whether the default is ever actually used, silently masking a dead fallback indefinitely. Converting the call to `mapping[key]` guarded by `try`/`except KeyError` makes the `except` branch a distinct, coverage-tracked line: if the non-unit suites never execute it, that's direct evidence the fallback is dead and the key is always present, and the `except` branch can be removed the same way any other confirmed-dead branch is. This also tends to be faster than `.get()` when the key is present in the overwhelming majority of calls.

Running the non-unit suites requires `testcontainers` (Podman/Docker) and a `.env` with MongoDB connection settings; this sandbox has neither, so the dynamic techniques above are demonstrated but not exhaustively re-run here for every candidate branch or mapping access. Tasks below scope the dynamic audit per source module so each check stays small enough to run and revert independently during implementation, where that infrastructure is available.

## Goals / Non-Goals

**Goals:**

- Remove `src/` symbols reached only from `tests/`, and the unit tests that exist solely to exercise them.
- Remove `src/` conditional branches (including `.get(key, default)` fallbacks) proven unreachable with real MongoDB/pymongo-sourced values, deleting the dead branch outright with no replacement guard, assertion, or comment.
- Leave every branch that guards caller-supplied input (filters, projections, collations, admitted documents) untouched — those vary by design and are not dead code.

**Non-Goals:**

- Do not change any documented public API, cache semantics, or observable behavior for real MongoDB-backed usage.
- Do not add new defensive checks, error handling, abstractions, or permanent `assert` statements while removing dead ones — `assert` is a temporary local diagnostic during the audit, never a committed replacement for a removed branch.
- Do not treat a branch as dead solely because unit tests are its only current coverage without also checking, per the second technique, whether real driver data can reach it — unit-test-only coverage and dead code are different findings requiring different evidence.

## Decisions

- **Static pass first, dynamic pass second.** The static cross-reference (definitions vs. non-test call sites) is cheap, exhaustive, and free of false positives for the "called only by tests" category, so it runs once over all of `src/` before any dynamic check. Alternative considered: relying only on the coverage-diff technique from the proposal's `## Why` (full-suite vs. non-unit-suite coverage) — rejected as the sole technique because a symbol can show non-zero non-unit coverage while still being dead in isolation (e.g., covered as a side effect of a shared fixture), whereas a direct call-graph cross-reference is unambiguous.
- **Assert-and-rerun as a temporary diagnostic, delete for the real commit.** Every always-true/always-false branch candidate is proven by temporarily replacing the guard with an `assert` and running the non-unit suites; once that confirms the alternate branch is unreachable, the committed change deletes the branch and the temporary `assert` together, exactly as demonstrated for `_wall_time_seconds`. The `assert` never lands in the committed diff — it is scratch scaffolding for the proof, not a permanent contract statement. Alternative considered: reasoning from MongoDB/pymongo documentation alone — rejected because documentation can be incomplete or version-specific, and the project already treats "not derivable from the code" claims as requiring verification (see `CLAUDE.md`'s "Pre-existing Issues" guidance).
- **`try`/`except KeyError` over `.get(key, default)` for driver-sourced mappings.** Where a candidate fallback is on a mapping MongoDB/pymongo produced, convert `.get(key, default)` to direct subscription guarded by `try`/`except KeyError` before running the non-unit suites: an always-uncovered `except` branch is itself the dead-code proof (no separate `assert` needed), and the conversion is kept permanently — it is faster when the key is almost always present, and it keeps the fallback's coverage visible going forward instead of it silently vanishing back into `.get()`'s default. Alternative considered: leaving `.get(key, default)` and reasoning about the key's presence from documentation alone — rejected for the same verification reason as above, and because `.get()` provides no ongoing coverage signal if the assumption ever changes.
- **Scope the dynamic audit to driver-sourced values only.** Conditionals over caller-supplied query documents, projections, or collations are excluded from the branch audit even where one arm looks rarely taken, because those arms exist to support legitimate caller variation, not to guard against an impossible MongoDB response.

## Risks / Trade-offs

- A branch that looks unreachable today could become reachable if a supported MongoDB version changes a response shape → the assert-and-rerun evidence is captured in the commit body for each removal, and CI continues to run the same non-unit suites on every change, so a future regression surfaces as a test failure rather than as a silently reintroduced guard.
- Deleting a test-only method could remove intentional public API surface (e.g., a documented convenience method awaiting its first caller) → check `README.md`/`docs/` for each candidate before deletion; if a symbol is documented as public API, leave it and record the finding instead of deleting it, per the proposal's `## What Changes` fallback.
- The dynamic audit needs `testcontainers` and a working `.env`, unavailable in this planning session → tasks are scoped so each module's audit is independently runnable and revertible in an environment that has that infrastructure, and no deletion lands without the corresponding suite run.
