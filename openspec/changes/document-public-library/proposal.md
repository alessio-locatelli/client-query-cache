## Why

The library cannot make accurate public claims until its construction, read behavior, lifecycle, limits, recovery, and measurement boundaries are implemented. Stable user and operator documentation is therefore a distinct finalization task.

## What Changes

- Replace proof-of-concept README claims with verified installation, quick-start, and non-goal documentation.
- Publish API, migration, architecture, capacity, consistency, error, and operational guidance.
- Link benchmark evidence rather than making unsupported universal performance claims.

## Capabilities

### New Capabilities

- `public-library-documentation`: Verified user, maintainer, and operator documentation for the implemented library.

### Modified Capabilities

- None.

## Impact

- Affects README and documentation only after the dependent public behavior is complete.
