# Design

## Context

See `proposal.md` for motivation and the two deltas for requirements. Inspection at `55807be3` followed the actual constructor imports: both managers instantiate `_shared_index.LocalCacheCore`, and `_shared/coordinator.py` instantiates `SharedOwnerCore`. Their common owner is `native/shared-index/src/local_cache.rs`, with shared publication in `local_cache/shared.rs`. `_core/native.py` supplies configuration, codec, key, error, and snapshot integration to those owners.

The old Python engine is imported transitively because `CacheCoreConfig` and `_core/__init__.py` still import its module. Its tests inspect Python LRU and namespace internals; native tests also use it as a differential oracle. Native extension exports make some purely developmental facilities appear live to compiler dead-code analysis. Coverage of such facilities is not evidence of production use.

## Goals / Non-Goals

The scope is the entire Python library tree and native implementation/binding tree, including orphaned symbols after the known removals. The production-purpose rule, verification behavior, and prohibition on relocating a comparison engine are owned by `specs/production-library-scope/spec.md`.

This change does not implement selective invalidation or change supported application read behavior. It does not rewrite Git history. Historical reports remain evidence for their recorded revisions; they do not justify keeping their engines, bindings, or workload variants in the current tree.

## Decisions

### D1. Delete the Python engine after extracting production configuration

Move `CacheCoreConfig` and its production defaults to `_core/config.py`, updating all production imports and runtime-resolvable annotations. Preserve the public root, synchronous, and asynchronous exports. Remove the obsolete `_core` package re-exports rather than leaving a reference-engine alias. The remaining package initializer must not eagerly load the removed dependency graph.

| Library target                                                                                  | Disposition and consumer evidence                                                                                                                                                                                                                                          |
| ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `_core/manager.py`                                                                              | Extract the configuration first, then delete the entire engine, Python captures, admission, lookup, and lifecycle implementation. Production managers do not instantiate it.                                                                                               |
| `_core/lru.py`, `namespace.py`, `retention.py`, `locking.py`, `lifecycle.py`                    | Delete completely with their exports and typing dependencies. Their production-tree consumers belong to the removed engine graph.                                                                                                                                          |
| `_core/entries.py::CacheEntry`                                                                  | Delete the Python engine record. Keep `AdmissionOutcome`, `LookupResult`, and miss sentinels: native integration and live collection adapters consume them.                                                                                                                |
| `_core/keys.py::IdentityCacheKey`, `NamespaceCacheKey`, `CacheKey`                              | Delete the Python storage-key records. `NamespaceId`, `AliasKey`, and canonical alias preparation still serve production native callers.                                                                                                                                   |
| `_core/snapshots.py::CacheStatistics` and `_RETENTION_INDEX`                                    | Delete the Python mutable counter implementation and its private lookup table. Preserve public snapshot/reason types, native snapshot assembly, `retention_counts`, and `StatisticsSource` used by OpenTelemetry.                                                          |
| `_core/canonical.py::_reference_canonicalize` and `_core/order_sensitive_keys.py::_reference_*` | These are production delegates, not an alternate engine: `keys.rs` calls them for custom mapping/sequence inputs. Rename them and corresponding binding argument/field names to describe generic production handling; preserve exact supported semantics.                  |
| Remaining Python modules                                                                        | The adapters, streams, codecs, eligibility, metadata, key helpers, telemetry, and shared transport have production consumers. Inspect individual residual symbols after deleting the engine graph; production imports of a mixed module do not justify its unused members. |

Alternative retention, a test-only copy, or a compatibility wrapper would preserve the duplicate implementation and contradict the requested outcome. They are not alternatives under the authorized scope. Extraction into one configuration module is routine; it requires no new architecture or dependency.

### D2. Remove development-only native exports and their implementations

Remove the following binding surface, registrations, stubs, and orphaned Rust code. A Rust operation genuinely used by the native production owner stays internal even when its redundant Python wrapper is deleted.

| Target                                                                                                                                                   | Evidence and action                                                                                                                                                                                                                                                          |
| -------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LocalCacheCore._ownership`, `_recency`                                                                                                                  | Called by tests, memory research, and cursor benchmarks; no production caller. Delete both.                                                                                                                                                                                  |
| `SharedOwnerCore._probes` and `Probes::snapshot`                                                                                                         | Only tests inspect this probe listing. Delete inspection while preserving production expiry, reservation, and metadata behavior.                                                                                                                                             |
| `LocalCapture.identity`, `generation_key`, `generation`, `availability_generation`, `released` Python getters                                            | Only test/harness consumers need these Python views. Remove the getters and protocol/stub properties; retain the actual Rust fields used by validity, admission, and GC. `namespace` and `release()` have real shared-coordinator callers and remain.                        |
| `ByteRelay`, `duplicate_tcp`, `relay.rs`, and relay tests                                                                                                | Only benchmark transport and binding tests consume this implementation. Delete rather than move the relay into another shipped extension.                                                                                                                                    |
| `EchoOwner`, `OwnerIndex.serve`, `echo.rs`, and echo tests                                                                                               | Only research floors, binding tests, and PGO training consume the echo server. Delete the server and its workload.                                                                                                                                                           |
| `Payload` and Python `OwnerIndex.store`, `release`, `snapshot`, `publish`, `unpublish`, `set_available`, `set_epoch`, `record_write`, `validate_capture` | Their consumers are low-level fixtures, research, or training; production publication/admission now uses Rust state operations. Delete the wrappers and `Payload` registration. Preserve the underlying Rust index, arena, and fencing algorithms used by `SharedOwnerCore`. |
| Python `SessionRing.drain`                                                                                                                               | Production `SharedOwnerCore.touch` calls this operation directly in Rust. Remove the Python export; keep the required internal Rust operation outside `#[pymethods]`.                                                                                                        |
| Required index/ring bindings                                                                                                                             | Construction, descriptor transfer, `published`, progress, capture enablement, session creation, drop counters, and queued admissions have coordinator/attachment callers. Keep these and the production reader interfaces.                                                   |

Use compiler diagnostics and a fresh per-symbol consumer audit to remove imports, constants, helper methods, OS wrappers, feature/dependency entries, and type annotations orphaned by these deletions. Do not preserve an export merely because PGO calls it or a stub declares it. Conversely, do not delete a Rust validity field because its Python getter was test-only.

There is no production transport alternative to select: the removed echo/relay implementations are not used by ordinary shared managers. Existing application IPC stays in the coordinator, attachment, index, ring, and frame implementation. Runtime/code-layout effects of removing the bindings and changing PGO inputs require D6's measurements.

### D3. Rehome tests around actual production behavior

Retain meaningful contract cases, parametrized directly over `LocalCacheCore` and applicable `SharedOwnerCore` modes. Replace differential comparisons with explicit expected outcomes and specification invariants. Simple expected-value state in a generated operation schedule is test data; it must not become another cache implementation with its own admission, eviction, or invalidation algorithms.

| Consumer group                                                                                            | Concrete conversion                                                                                                                                                                                                                                                                                           |
| --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tests/core/conftest.py`, `test_manager_state_machine.py`, retention/admission/alias/lifecycle/find tests | Construct the native production core. Express freshness, availability, eviction order, bounded capacity, and replacement behavior through results, snapshots, weak references, and complete operation schedules. Delete Python storage/lock implementation tests and mechanics-only cases.                    |
| `tests/core/test_native_owner.py`, `tests/shared_cache/test_shared_index_oracle.py`                       | Remove the reference factory and differential engine, inspection helpers, and manual publication oracle. Use production owner admission and reader results, plus existing key lifetime/cycle tests and observable metadata eligibility. No `_ownership`, `_recency`, or `_probes` replacement binding.        |
| `tests/stream_helpers.py`, stream/collection tests                                                        | Replace generation-getter polling with test-owned observation around the existing Python event router, delegating to real routing before signaling completion. This adds no library callback or decision replacement.                                                                                         |
| `tests/memory/`, cursor/family memory benchmarks                                                          | Measure native construction and churn. Replace Python index inspection with normal cache outcomes, public snapshots, object collectability, and repeated process-memory observations. Keep measured ceilings honest; a lower Python heap report alone does not prove native reclamation.                      |
| `benchmarks/record_write_invalidation.py`, `stream_startup.py`, stream-cost diagnostics                   | Use the actual native core and configuration module. Rename or remove measurements that only described the old engine's internal structures.                                                                                                                                                                  |
| `research/process_memory/measure.py` and historical native-local comparison selectors                     | Remove the current-tree reference mode. Maintain useful current production workloads; reproduce historical implementations from their already recorded Git revisions only.                                                                                                                                    |
| `research/invalidation_scope/guards.py` and experimental guard paths in `end_to_end.py`                   | Delete the monkey-patched Python engine subclass and experimental selection. Reuse data generation, oracle inputs, command accounting, and byte-metering infrastructure for production measurements as needed; do not retain the experimental invalidation implementation.                                    |
| `research/shared_index_floors/`, shared-find floor callers, and native-binding tests                      | Delete workloads for removed echo/manual-publication facilities. Keep tests of actual reader/owner behavior using production admission, including OS-backed error/resource cases.                                                                                                                             |
| `benchmarks/stream_cost/shared_cache/owner.py` and fault workloads                                        | Replace `ByteRelay` dependency using the repository's existing harness-side socket proxy/fault facilities outside the package. Preserve directional accounting, backpressure, pause/recovery, and cleanup checks for retained workload claims; remove obsolete transport-floor cells.                         |
| `scripts/pgo_training.py`, `tests/test_pgo_training.py`                                                   | Remove `echo_roundtrip` and manual-publication setup via removed bindings. Seed shared state through `SharedOwnerCore` admissions and exercise actual reader, queue, touch, invalidation, and key paths without MongoDB. Update training manifests and profile-completion expectations to the retained paths. |

Keep ordinary native unit tests, their compile-time support helpers, and Loom models in their current crate/module assembly. `lib.rs`, `memory.rs`, and the individual modules already gate these sources with `cfg(test)` or `cfg(loom)`; normal extension builds enable `python` without those test configurations. This follows Rust's [conditional compilation rules](https://doc.rust-lang.org/reference/conditional-compilation.html#test). Cases tied exclusively to D2's deleted runtime facilities disappear with those facilities; tests of retained production behavior stay.

Do not introduce path-based test roots, split memory modules, rewrite snapshot copying, or relocate synchronization adapters merely to change file locations. Preserve the established unit/model/lint/coverage commands, adapting only assertions or source expectations affected by actual runtime deletions. Test helpers must remain unavailable in normal runtime builds, and may not become an alternate cache engine or an exported inspection API. Source-archive inclusion is evaluated separately in D5.

Alternative: moving all tests outside `src/` changes module assembly and adds review work without removing more runtime code. It can reduce test fidelity and is unnecessary for this cleanup. Existing conditional compilation provides the needed boundary; task 3.2 verifies it against the release configuration and retained tests. No separate architecture or prototype is required.

### D4. Reconcile architecture guidance and active work

Update `docs/development/architecture.md` and `shared-cache.md`: storage authority is native for both manager modes, cursor accumulation uses `EncodedArray`, and the former Python lock hierarchy is not the production design. Document the application execution path in one canonical location and link it from supporting guides. Public configuration references use public imports, preserving the existing API. Remove the claim that configuration exists for the benchmark suite when its production purpose is telemetry configuration. Review affected Context7 rules by meaning.

The accompanying planning revision reconciles `opt-in-selective-invalidation`; its proposal, D2–D3, D6, and tasks are authoritative for the feature's native integration and verification. Apply this cleanup first or rebase the feature onto its completed source. At cleanup completion, check that the active feature artifacts still match the resulting production paths and contain no dependency on D1–D3's removed engine or instrumentation. All feature implementation checkboxes remain pending.

The `complete-native-coverage` change remains responsible for its existing coverage gate work; this cleanup adapts its expectations for removed runtime facilities without completing or weakening its tasks. The worker-fault recovery change retains its behavioral acceptance, with harness transport moved out of the library. No new issue or research study is required to preserve those commitments.

### D5. Verify deletion as a complete dependency closure

At implementation completion, trace both public manager roots, shared-owner startup, native module registration, production delegates, and runtime type imports again. Inspect every remaining runtime member whose only callers are outside the production roots. Remove newly orphaned implementations in the same change, including exported PyO3 methods that compiler dead-code analysis treats as reachable. Compile-time-only unit/model code is classified by the build configuration, not by its directory name.

Task 5.1 records the following acceptance evidence. Wheel and source-distribution inspections are separate; a clean checkout or passing tests alone cannot establish either artifact's contents.

| Area                     | Acceptance evidence                                                                                                                                                                                                                                                                               |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Python runtime           | Installed file/import inventory contains no duplicate Python engine, reference storage algorithms, or unused compatibility wrappers. Trace mixed-module members separately.                                                                                                                       |
| Rust extension           | Inspect the actual loaded extension's export surface and retained bound methods: no benchmark relay, echo server, inspection replacement, or training-only binding.                                                                                                                               |
| Production helpers       | Verify supported custom mapping/sequence and codec behavior, including the required Python delegates called by native production code.                                                                                                                                                            |
| Dependencies             | Re-run consumer tracing and existing dependency/dead-code tooling after removal; no library or symbol remains solely for a deleted runtime facility.                                                                                                                                              |
| Wheel                    | Inspect a fresh installation from the built wheel, its resolved module paths, runtime files, extension exports, and stubs; exclude stale editable builds from the evidence.                                                                                                                       |
| Source distribution      | List and classify archive contents, distinguishing required build tooling and compile-time-only tests/models from runtime files. Build/install the archive in a separate environment and audit the resulting runtime too. Neither source archive nor wheel retains a duplicate comparison engine. |
| Behavioral compatibility | Exercise supported sync, asyncio, and shared-cache operations, errors, telemetry, and public imports through both artifact installations using the retained contract suites.                                                                                                                      |
| Performance              | Attach D6's matched installed-build evidence and resolved or explicitly approved adverse effects.                                                                                                                                                                                                 |

Use `rg`, structural navigation, existing type/lint/coverage tooling, and built-artifact inspection. Do not add a permanent source scanner or absence-only test duplicating this audit. Record the final concise deletion/production-purpose rationale in the change's design, and keep disposable call-site inventories under `/tmp/agents/`.

### D6. Measure the production build after removal

Build matched release wheels from frozen main and the cleaned source, with their own valid production PGO training profiles and the same interpreter/toolchain. Run fresh-process import/startup/RSS controls and focused public sync/async local/shared warm, cold, admission, and invalidation comparisons. Hold data, native residency, telemetry mode, and workload constant. If the harness proxy changes, run the same new harness against both installations and measure its CPU separately. Do not compare a native candidate to an in-tree Python engine.

Compare retained test durations separately from deleted mechanics-only tests; fewer tests alone cannot establish faster production execution. Check the built wheel and source-distribution install under the existing release workflow. Record repeatable runtime/resource effects, uncertainty, and commands in a concise maintainer summary; raw data remains untracked. Investigate every reproducible slowdown and obtain approval for any material adverse trade-off under the repository policy. No benchmark runs are authorized during this planning turn.

| Path                    | Expected resource effect before measurement                                                                                                   |
| ----------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Fresh Python import     | Fewer class definitions and imports after configuration extraction; native binary contains fewer exported implementations. Magnitude unknown. |
| Ordinary cache hit/miss | Native algorithms and remote-call count stay unchanged; removed code and PGO changes can affect layout and require matched measurement.       |
| Native tests/models     | Existing compile-time-only unit/model assembly stays; no additional application runtime work.                                                 |
| Fault benchmark         | Harness-only transport replacement may change observer cost; it cannot be attributed to the library.                                          |

### D7. Reconcile the complete evaluation specification

Audit all 20 requirements in `process-local-cache-evaluation` against the effective delta. Sixteen are modified; `Qualified native integration completes in the same change` is removed as the completed backend-migration gate. The three unchanged requirements are `Native ownership preserves ordering and reclamation`, `Opaque equality uses a revalidated candidate version`, and `Integrated development checks precede long acquisitions`: they govern ongoing correctness or conditional preflight and do not require a reference engine.

The delta is authoritative for all updated measurement and reporting language. It preserves complete-work comparisons, residency, contention, resource accounting, preregistration, uncertainty, regression approval, and reproducible source while using independently installed production builds. The completed migration does not impose its historical unconditional full campaign on this cleanup; any broader campaign needs a registered validation reason. Historical reports stay attached to their recorded revisions.

## Risks / Trade-offs

- Losing tests while deleting an oracle → preserve the contract cases in D3 and review the retained invariants against the cache specifications.
- Keeping test helpers under a new name → D5 requires a production consumer, including for extension methods and training-only paths.
- Mistaking generic production delegates for obsolete references → D1 identifies their actual native call sites and preserves custom-value semantics.
- Removing assertions tied to deleted facilities can obscure coverage of retained behavior → verify the existing native/model/coverage paths without broad new exclusions.
- Concurrent implementation of selective invalidation → complete this cleanup first or rebase that work onto it; never maintain both engines to make the branches easier to merge.

## Migration Plan

This is a source cleanup with private interface removal. Extract required configuration and port contract tests before deleting their dependencies, then remove the native development surface and adapt tooling. Each part lands its own verification and documentation. No data migration, alternate engine, or compatibility module is introduced. This turn creates plans only.

## D5 outcome

The audit removed additional runtime members that only tests or benchmarks consumed: the owner pause and history-loss hooks, the encoded identity admission, and the epoch and snapshot getters (their harness equivalents now live in `benchmarks/stream_cost/shared_cache/owner.py` and `tests/`). `ExclusiveProbability` and `JsonDict` remain as annotation vocabulary used by public dataclasses. Wheel and source-distribution inventories and the D6 measurements are in `reports/remove-nonproduction-library-code/summary.md`.
