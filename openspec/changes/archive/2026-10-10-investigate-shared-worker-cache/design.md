# Design

## Context

See [proposal.md](proposal.md#why) for motivation. These are observations from the planning checkout, not new prototype results:

| Evidence                                                                                                                                                                                                       | Consequence for this investigation                                                                                                                                           |
| -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Both managers construct `CacheCore` and their execution model's `ChangeStreamCoordinator`; `shared_budget_bytes` is shared only inside that core.                                                              | Merely sharing configuration or upstream events does not share resident values.                                                                                              |
| `_core/entries.py` stores immutable BSON bytes; `_core/manager.py` encodes admission values and decodes hits with the requesting codec.                                                                        | An encoded-value boundary can avoid encoding the same value again for IPC; changing that boundary needs standalone differential checks.                                      |

Keep these objects in their authoritative core. |
| `_core/codec.py` fingerprints custom registries by Python object identity; query-family hashes and canonical keys are local Python objects.                                                                    | Neither object identity nor Python's randomized hash is a portable cache key.                                                                                                |
| Async collections and cursor hooks currently call the synchronous core directly.                                                                                                                               | A blocking remote substitute would block the event loop. Collection and cursor execution boundaries must support awaited cache access.                                       |
| Metadata caches belong to each manager and use namespace/index generations.                                                                                                                                    | Shared values require authoritative generation checks before trusting local eligibility or aliases.                                                                          |

The [completed report](../../../../docs/development/research/shared-invalidation-feasibility.md) measured 1,024 documents of 4,135 BSON bytes each, or about 4.05 MiB per manager. Eight workers retained about 32.37 MiB of cached BSON and about 356.7 MiB aggregate worker USS. Its stream-only comparisons had upper bounds below 0.05 CPU seconds/second, so no coordinator prototype ran. Its retrospective cleanup and idle-poll limitations remain applicable to those historical results. They are not evidence about shared-value latency, shared-page memory, or recovery.

[Issue #87](https://github.com/alessio-locatelli/client-query-cache/issues/87) owns shared invalidation with local values. This change does not reopen its gate or repeat its stream-only matrix. [Issue #24](https://github.com/alessio-locatelli/client-query-cache/issues/24#issuecomment-5765918050) rejected MongoDB-persisted cache state because it changes latency and failure semantics. [Issue #197](https://github.com/alessio-locatelli/client-query-cache/issues/197) supplies the application benchmark context, including concurrent writes and worker recycling; it does not prescribe shared storage.

Existing `cache-core` and `cached-read-api` Purpose text says process-local, and the stream ownership requirement says one cursor per manager. Conditional integration therefore needs the attached deltas and Purpose updates in task 3.1. The active changes for Python compatibility, numeric configuration, and usage contracts are outside this change; preserve their work and reconcile touched contracts against them before integration.

## Goals / Non-Goals

The design boundary is one trusted application worker group on one host, with one authoritative cache state and one stream owner per active database. Correctness contracts live in the delta specs; numerical acceptance policy lives below. The experiment must explain both the steady-state access path and its limiting resource.

Cross-host availability, durable cached data, consensus/election, arbitrary external consumers, per-write freshness barriers, and automatic global discovery are excluded. Shared storage does not eliminate caller-owned decoded results, native driver buffers, or admission candidates. A group budget bounds resident encoded entries, not whole-process memory.

## Decisions

### Architecture alternatives

The following table selects an experiment order, not a shipping technology. Task 1.2 records source and feasibility checks; task 1.3 implements only the representative candidates warranted by those checks.

| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Independent managers                                                          | Existing correctness and lifecycle; no cache IPC; parallel local hits.                                                                                                   | Duplicated resident values and streams.                                                                                                                                                                             | Mandatory baseline. No additional architecture research is needed.                                                                                                                                              |

Primary mechanism references: [multiprocessing contexts and managers](https://docs.python.org/3/library/multiprocessing.html), [shared-memory ownership](https://docs.python.org/3/library/multiprocessing.shared_memory.html), [LMDB transactions and buffers](https://lmdb.readthedocs.io/en/release/), and [PyMongo process safety](https://www.mongodb.com/docs/languages/python/pymongo-driver/current/connect/mongoclient/#multiple-forks). These establish mechanism constraints, not expected benchmark wins. In particular, unrelated Python processes can have separate shared-memory resource trackers; ownership cannot be inferred from a segment name.

### Prototype boundary and code reuse

Use a research runner under `benchmarks/stream_cost/shared_cache/`, with a `run` entry point. The first slice supports `_id` `find_one`, one generic namespace read, shared evictions, and database events. It must execute through research adapters around actual supported facades, clearly marked as prototype integration. A transport-only echo loop is diagnostic, never decision evidence. Production public exports and constructor changes wait for the gate.

Extract the minimum internal encoded-entry seam in `_core/manager.py`: validity, eviction, statistics, aliases and capture release remain implemented once. Existing standalone methods retain their current object/codec interface and call that seam. Workers encode native results once and decode returned stored BSON locally; the coordinator never runs application codecs. No decode/re-encode in the coordinator just to transport a value. Confirm this against custom-codec and cursor-capture tests before using it for measurements.

Define coarse read-selection and admission operations, not an RPC for each current core accessor. A hit operation checks database availability, namespace/index metadata generations, alias/shape validity, and selects an encoded entry. A miss returns an opaque coordinator-owned admission handle captured before native execution. Workers keep executing MongoDB queries through their own clients with the existing eligibility and primary/majority rules. A completed result returns through one guarded admission operation; interrupted consumption discards the handle. Handle tables have per-session and group limits and are reclaimed on session closure or a registered finite lifetime. An expired handle rejects admission without changing the already successful native result.

Local metadata may be retained as an optimization only when a selection request validates its epoch/index generation. A mismatch returns a refresh instruction; discovery happens outside core locks, and publication carries the observed generation for revalidation. Normal hot hits target one request/reply, while misses need selection plus admission and possibly cold metadata refresh. The benchmark measures those paths separately. Cache misses may duplicate native queries under contention; bounded single-flight is an alternative only if profiling in task 2.2 shows stampedes matter, and its wait/cancellation cost must then be compared before integration.

Canonical wire keys retain ordered mappings, BSON distinctions, codec profile and every output-affecting shape input. Transmit tagged canonical values rather than Python hashes or `repr`. The first profile uses the built-in BSON registry. Custom registries and any unsupported key/codec profile execute natively, with an observable reason; no pointer identity is transmitted. Task 3.1 enumerates supported portable profiles and their bypass rules before production work. Application transformations and client-side encryption require separate isolation or bypass; shared decoded plaintext must never cross an incompatible security profile.

Sync adapters wait on blocking local sockets outside shared core locks. Async adapters use event-loop socket operations and request IDs, preserving cancellation and native cursor call shapes. A thread-executor adapter is simpler but adds scheduling and cancellation ownership; task 1.2 compares it as a diagnostic, and task 3.1 records the final choice. An async manager cannot hide blocking RPC behind the existing synchronous `cache_core` property: expose a synchronous local observation handle there for shared mode, and use a private awaited backend for reads. Document that shared advanced mutation primitives are unavailable instead of simulating synchronous network calls. Standalone advanced access remains unchanged.

### Ownership and transport

The application owns an explicit coordinator owner outside worker lifetimes. Candidate API names for task 3.1 are a context-managed `SharedCacheCoordinator` yielding `SharedCacheEndpoint`, with `shared_cache=endpoint` on both existing managers. No attachment option selects today's standalone behavior. Passing a worker budget or await-time override conflicting with the group configuration fails construction; group configuration is fixed by its owner, not silently ignored.

An explicit owner is preferred to lazy spawning/election by each worker: the latter races during startup and recycling and needs orphan detection and leader replacement. An automatically managed child is useful for simple scripts but cannot become a hidden per-worker coordinator. Task 1.2 validates the explicit launch hook with Uvicorn spawned workers and Gunicorn pre-fork recycling; task 3.1 fixes the supported example and API. No additional election mechanism is planned.

Create the coordinator's MongoClient inside its process from application-provided configuration or a child-local factory. Create each worker's client and attachment after worker start. Never transfer live clients, loops, locks, or managers across fork. Use a caller-selected multiprocessing context when the owner spawns a process; do not mutate the global start method. A PID check rejects an inherited attachment before touching its inherited locks or transport. Merely importing/preloading the application starts no cache processes or streams.

Start with a Unix-domain socket in a private owner-created directory. Restrict permissions and authenticate attachments with a group capability supplied through application configuration; never log it. An endpoint name or a claimed MongoDB URI is not authorization. Each endpoint represents one explicitly trusted principal/deployment/security profile, with a fixed database allowlist. Different tenants or principals use different owners/endpoints. Equivalent authority is an application responsibility and a documented trust boundary, not something inferred from usernames or endpoint strings.

Use established socket/event-loop primitives and bounded length-prefixed BSON control frames with raw BSON payloads. Reject unsupported versions, oversized/truncated frames, unknown operations, and invalid session handles. Bound per-connection queued bytes and outstanding requests, total connections, capture handles and send duration; the prototype registration sets the numeric limits. Slow clients are detached without stalling invalidation or unrelated clients. No arbitrary Python object deserialization, network listener, disk persistence or custom broker is required. If Unix sockets cannot support the target platform, shared mode is explicitly unsupported there; standalone mode retains its platform support. This limitation is preferable to an unmeasured cross-platform transport.

### Ordering, uncertainty and restart

The core and existing `route_change_event` remain the authority for the generation rules specified in `cache-core`. Selection has the same snapshot boundary as today's lookup: an invalidation processed before selection prevents an old hit; an event concurrent with a previously selected response does not retract that response. A started hit cursor retains its isolated snapshot. Do not claim that transport supplies a MongoDB commit barrier.

Attach a fresh incarnation to each coordinator start, a fresh session to each connection, and request IDs plus availability generation to captures and replies. Old-session responses and admissions are rejected after reconnect; RPC deadlines are measured from worker issuance, so a paused worker cannot accept an arbitrarily old buffered reply. Retry selection only as a new operation after a new handshake. Admission can be discarded on timeout; never repeat the native database read merely because cache publication failed. Unknown IPC completion has no write side effects beyond expendable cache state.

Reuse database supervisors, expanded-event projection, startup cooldown, router, and resume/clear logic. Add a small progress observation seam if needed: each completed upstream poll, including empty batches, advances the coordinator's local progress observation. `stream_polls` cannot substitute for completed wire `getMore`. The default research freshness check rejects new selection/admission after three seconds without completed upstream observation; a heartbeat thread alone cannot renew it. Refresh failures make that database unavailable and advance availability before clearing. This is a failure-detection lease, not a bound on commit-to-invalidation delay. Production values remain subject to the same fault gate and documented client timeout interaction.

| Failure                                                     | Detection and action                                                                                                               | Re-entry                                                                                                                         |
| ----------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Coordinator exits, hangs, or replies after its RPC deadline | EOF/failed connection, request deadline or invalid session rejects cache use. Execute native reads; retain no worker result cache. | Owner explicitly restarts with empty core and new incarnation; handshake and healthy database watch precede selection.           |
| Watch stalls while RPC still works                          | Check upstream progress at each selection/admission; expiry disables that database before responding.                              | Existing recovery plus a fresh upstream observation; advance availability so pre-expiry captures fail.                           |
| Stream disconnect or resume history loss                    | Existing supervisor sets unavailable; history loss clears affected namespaces and metadata generations.                            | Healthy watch plus matching availability generation; reads spanning transition cannot admit.                                     |
| Worker closes, crashes or is recycled                       | Session closure or bounded session/capture expiry reclaims its handles and buffers.                                                | Replacement starts with a new client/session and no inherited admission ownership. Other workers retain group state.             |
| Queue saturation or cancelled async request                 | Bound outstanding work; discard/detach or bypass on timeout. Release capture ownership even if cancellation races admission.       | New operations use live session; an accepted late cache admission still must pass current generation guards.                     |
| Namespace/index changes during discovery or admission       | Authoritative epoch/index generation check rejects the obsolete observation or capture.                                            | Refresh metadata and retry selection; no old alias is trusted locally.                                                           |
| Owner shutdown or duplicate startup                         | Exclusive endpoint ownership prevents a second live owner; shutdown rejects attachments and selections before waiting for cleanup. | Only the owner removes its resources; a replacement uses a fresh incarnation and core. No automatic takeover of a live endpoint. |

With mapped payloads, immutable selection tokens also need a safe copy/pin protocol. Workers must never dereference a reclaimed/reused slot after eviction or owner loss. A paused or crashed reader cannot pin unbounded old generations; count pins and fragmentation outside resident entry bytes and fail that candidate if safe bounded reclamation cannot be shown. The socket candidate avoids this additional correctness problem.

### Measurement protocol

Task 1.1 preregisters the baseline calibration procedure and decision criteria; task 1.6 freezes the resulting workload in the current registration's `reports/shared-worker-cache/v<registration>/config.json` before any candidate timings, together with a Markdown registration explaining units, estimands, and limits. The useful JSON stays below 200 lines. Changes after a failed setup or exploratory profile get a new registration version and restart affected comparisons; preserve the old outcome. Raw output stays under ignored `benchmark-reports/shared-worker-cache/` and is never committed.

**Topology and workload.** Use the existing disposable MongoDB replica-set owner and container bridge; no production access or system changes. Record revision, config digest, Python/PyMongo/transport versions, host CPU and available memory, MongoDB image, CPU/memory limits, start method, codec, concerns, compression and all client timeouts. Start with one database, one ordinary catalogue collection and 16,384 shared documents with 4 KiB payload fields and nested BSON values. Record actual encoded entry bytes; a 96 MiB BSON budget for each independent manager or for the single group must fit the complete hot set. Every worker cycles the entire same hot set during priming; report and exclude priming cost from hot windows but retain it as startup evidence. Raw reads perform identical decode and application checksum work without retaining the data. Shared misses go through worker clients, not coordinator queries.

**Baseline capacity calibration.** Calibrate direct MongoDB and independent-manager paths only, with the same topology, instrumentation, concerns, decode/checksum work and per-worker concurrency of four used by the fixed-work comparisons. Cover their required worker counts and execution models, including the active and mixed schedules, cold misses and payload/cursor sensitivity profiles. Calibration cannot use shared-candidate results and is excluded from promotion inference. Preregister this selection rule before calibration:

- Collect three closed-loop baseline windows per required cell, with fresh state and the applicable priming or cold setup. Preliminary active probes use the nominal cadence of 200 updates per 60 seconds; final schedule validation follows below. Each window lasts 15 seconds, except cold probes end at 10,000 distinct identities or the time limit, whichever comes first, and use actual elapsed time without cycling warmed keys. Use the lowest observed completed throughput across both baseline paths and every required cell of each workload family.
- Select one integer aggregate primary rate equal to 75% of that minimum, capped at 6,000 reads/second. Select cold-miss and sensitivity rates by the same rule for their respective baseline cells, capped respectively at 1,000 and 500 reads/second and at the primary rate. These are ceilings, not assumed sustainable loads. Each selected rate remains common across paths and worker counts in its family.
- Validate each selected rate with three baseline-only open-loop repetitions at every required cell. Each must complete at least 99% of offered work inside the application window, without errors, queue overflow or a growing backlog. If a family fails, halve its common rate and repeat validation, allowing at most three rate attempts in total. No sustainable rate means an inconclusive setup, not rejection of shared caching.
- Preserve the registered request-sample floor when lowering the rate: each hot and active path/run window lasts at least its nominal duration and long enough to offer 10,000 / 0.99 requests to each gated percentile population (including each model in the mixed group); cold windows still offer 10,000 distinct identities. Cap each window at 120 seconds. The 10,000 completed-sample floor applies separately to each path/run percentile population used for promotion, not pooled across confirmation blocks; cold windows must complete all 10,000 identities. Freeze the resulting durations before open-loop validation. Active schedules deliberately retain 200 writes per run, spread over that duration, so their cadence scales with the selected duration. Open-loop baseline validation and candidate comparisons replay exactly that final write schedule. If the sample floor cannot fit the cap, report an inconclusive setup rather than quietly weakening the floor.

Retain a concise calibration table, the selected rates/durations and all failed attempts in `registration.md`; keep raw calibration output untracked. Finalize and hash the configuration only after all baseline validations pass. Later baseline overload invalidates the affected comparison and calls for a new baseline-only calibration and registration before rerunning every affected path; never lower load only for the candidate. The candidate capacity staircase below remains a separate maximum-throughput experiment.

**Experiment sequence, keeping the matrix narrow.**

1. Instrumentation smoke uses 256 documents and short windows; it cannot pass the decision gate. Diagnostic socket/manager/async-adapter comparisons are labelled exploratory and only choose the first complete prototype. A candidate that cannot safely store or share the actual entries stops here.
2. Hot screening compares direct, independent and the first shared candidate at 1, 4 and 8 workers in sync-only and asyncio-only groups. Use six counterbalanced exploratory blocks, 10 seconds of untimed post-prime warmup and nominal 30-second windows, extended only as determined by baseline calibration. For each cell replay the frozen primary aggregate rate, equal work per worker, at concurrency 4 per worker; both models use the same concurrency. Issue times are open-loop; queue delay is part of request latency. At most 256 requests may be outstanding per worker; overflow records rejected offered work and invalidates the required-load gate. Screening reports point estimates and ranges only and can stop a candidate with an observed failed condition, but cannot promote one. Surviving candidates collect twelve fresh independent confirmation blocks at 4 and 8 workers; screening samples are excluded from promotion inference. One-worker results remain descriptive. This phase establishes observed memory and latency under equal demand, not maximum throughput.
3. A short, separately labelled closed-loop capacity staircase at 1, 4 and 8 workers increases per-worker concurrency through 1, 4 and 16, with three counterbalanced 15-second windows per path/model/point. Retain all points, throughput and latency, and report the first saturation point. It informs a practical capacity limit; it cannot replace the fixed-work CPU comparison. Freeze the staircase and its stopping rule in the registration. Stop increasing concurrency after two consecutive points fail to improve throughput by 5% or violate the latency gate; do not add workers just to find an impressive maximum.
4. Only candidates still eligible run active comparisons at 4 and 8 workers, both execution models: the frozen primary aggregate read demand, 200 independent updates over the calibrated active duration (nominally 60 seconds), and twelve independent counterbalanced blocks. Freeze read keys, write targets, values, and timestamps by seed. Retain six 20-event contiguous lag windows separated by 16 events per run, with the same 200-event delivery completeness check used by the earlier collector. Include bounded drain, and charge its CPU separately. Add one eight-worker mixed group, four sync/four asyncio, with the same schedule, twelve blocks and three paths; this verifies coexistence without multiplying every earlier cell.
5. Measure cold misses separately at four and eight workers in both models: warm clients and metadata, leave the entry store empty, then replay 10,000 distinct existing catalogue identities once at the frozen cold-miss rate, with twelve independent counterbalanced blocks and the three paths. This is intentionally unprimed and excluded from hot-memory and hit gates. It supplies miss percentiles without pretending that rare invalidation misses in the active phase have a stable P99. Include selection, native execution and attempted admission in the measured miss latency.
6. At eight workers only, use a preregistered 64 KiB document profile with enough documents to retain approximately the same encoded working-set size, and a 16-document sorted find result below `max_entry_bytes`. Compare the three paths in both models with three blocks at the frozen sensitivity rate. These are copy/codec and cursor sensitivity checks, reported separately; they cannot establish a new supported envelope by themselves.
7. Fault trials are separate from steady-state inference. Use four workers including both models, deterministic injection points, and five repetitions per case in the failure table. Include coordinator termination and restart, coordinator pause past deadline, watch pause with RPC alive, stream interruption, unavailable resume history, a killed worker with an outstanding capture, replacement worker join, slow socket reader, malformed peer frames, and shutdown/cancellation during startup or publication. Record detection, first safe cache readiness, first post-recovery hit and full rewarming as separate durations. Reuse `tests/stress/helpers.py`'s processed-event oracle and stream faults where possible; add real process death and transport faults rather than relying entirely on mocks.

If a second architecture is justified by a measured bottleneck, compare at the failing four/eight-worker cells first; preregister its recommendation as a second candidate. A surviving second candidate repeats the complete required protocol. Do not run a cartesian product of transports, payload sizes, await times, platforms and worker counts.

**Accounting.** Collect user plus system CPU for all workers, coordinator, helper processes and harness, plus MongoDB container CPU. Identify byte-proxy and sampler CPU exactly once. The promotion CPU total sums workers, coordinator, deployment-required helpers and MongoDB; separately report harness/observer CPU and the experiment-wide total, so external measurement work cannot dilute a deployment cost increase. Embedded instrumentation remains in its measured owner's counter and its effect is disclosed through the overhead calibration below. Report CPU/window and CPU/completed request alongside demand, completions, errors and saturation; equal fixed-work comparisons require at least 99% of scheduled reads completed without errors within bounded drain. Include idle coordinator CPU as overhead and retained warmup/startup costs separately.

Sample worker/coordinator RSS, USS and PSS at matched barriers and 200 ms cadence. Sum simultaneous PSS for a group, so common mapped pages count proportionally once; never sum RSS or USS alone and call it actual shared memory. If a segment or file has resident pages outside these mappings, measure and add that owner once. Include resource trackers, queue buffers, keys, metadata, pinned payloads, decoder/native cursor buffers and peak admission copies. Record MongoDB container resident memory separately with the metric's cache/page accounting scope, plus harness memory. Do not add overlapping container and process memory counters. Report steady group PSS, sampled peak group PSS, resident payload, empty-client baseline, and application-plus-database totals. Missing shared-page or server-resident accounting blocks a total-memory claim.

Use dedicated MongoDB byte paths for workers, coordinator, writer and observer; record sent/received separately. Count actual socket bytes including framing, plus queued bytes and shared-memory copies/pins for applicable candidates. A mapped load is memory traffic, not zero-cost IPC. Record actual successful stream openings, live cursors at barriers, reopenings, getMore and relevant event counts; exclude observer cursors from the group ownership count without hiding their costs. Preserve per-worker and aggregate P50/P95/P99 for cache hits, cold misses, recovery bypasses and end-to-end requests, with sample counts. A shared-storage miss is not a cached hit merely because it avoided a manager activation.

Profile only representative diagnostic windows using existing profiling tools and process counters: BSON encoding/decoding, transport waits/copies, context switches, core lock wait, coordinator utilization and queue depth. Report instrumented and minimally instrumented windows separately. Calibrate observer overhead with matched samples at the same topology and four workers; disclose its CPU, memory and latency effect rather than silently subtracting it. Unsupported metrics fail setup visibly or are labelled unavailable and cannot support their associated gate.

**Inference.** Promotion uses twelve fresh independent paired confirmation blocks as its minimum and fixed maximum per required cell, with identical schedules and counterbalanced path order. Every block recreates clients, workers, coordinator, data and cache, and records host load and run order; unresolved carryover or correlated scheduling invalidates the claimed independent-block analysis. Thousands of requests within a block do not increase this independent sample count. Freeze paired ratio/delta estimands, missing-data rules and inference code before sampling. Extend the existing resampling utilities to retain whole paired blocks, using 200,000 seeded draws instead of enumerating the infeasible twelve-block Cartesian product. Report nominal 95% intervals for one candidate's all-must-pass conjunction. If a second candidate is eligible for recommendation, adjust candidate selection to 97.5% intervals for each candidate; do not perform hundreds of component-wise adjustments. Check a second registered resampling seed and leave-one-block-out sensitivity; a changed promotion verdict is inconclusive. State exchangeability, finite-sample and bootstrap approximation limitations. Every required model/count/case must pass; failed or missing cells are not averaged away. At the twelve-block cap, any unresolved bound or instability means deferral, with no adaptive extra sampling to obtain a passing result.

Lag uses the existing host/primary calibration and uncertainty rules, at 50 ms cadence for the 500 ms absolute ceiling. Promotion resamples the twelve outer paired run blocks, retaining each run's six complete capture windows together and expanding for clock uncertainty; it does not assume six windows from one run are six independent experiments. Measure same-host fault durations with one monotonic timebase. Each path/run percentile population used for a required fixed-load P99 gate needs at least 10,000 completed samples, plus the outer-block uncertainty estimate; samples cannot be pooled across the twelve blocks to meet this floor. This is a percentile-resolution floor, not evidence of independence. Smaller diagnostic populations are labelled descriptive. Inconclusive bounds fail promotion. Capacity staircases and sensitivity/fault trials retain individual runs and descriptive ranges; they make no simultaneous statistical confidence claim.

### Decision gate

These are proposed engineering acceptance targets, fixed before new measurements; they are not claims derived from the previous report. The default intended envelope is 4–8 same-host workers with the primary hot-set profile. Both execution models and the mixed active group are required. One-worker results expose overhead but do not have to establish a memory benefit.

| Coherence and isolation   | Every deterministic safety/failure case passes; no wrong-scope result, post-invalidation stale selection, or obsolete admission. No numerical saving can override a safety failure.                                                                                                                                                                                                                                                                                                                  |

| Request performance       | Shared request P99 is at most 1.25 times independent and no more than 1 ms worse, using upper bounds. Miss P95/P99 do not exceed direct by more than 1 ms. ### Decision record

The socket owner was the first and only built candidate; the bounded checks in task 1.2 kept the coarse `multiprocessing` proxy as a control and the event-loop asyncio adapter over a thread executor. Registration version 4 froze after three earlier calibrations ended inconclusive on harness setup failures. Screening stopped the candidate: request P99 and total CPU per request exceeded their criteria in every unaffected four- and eight-worker cell, although memory, hit-latency and traffic criteria passed. Profiling placed the excess in per-request owner work, below the second-candidate payload trigger, so no second prototype was built. Integration is deferred and section 3 does not apply. The [research report](../../../../docs/development/research/shared-worker-cache-feasibility.md) holds the measurements, limits and reproduction commands; the research runner, adapters, registrations and the `_core` encoded-entry seam stay in the tree, and a clean detached worktree at `8407b03` passed the documented smoke run.

## Risks / Trade-offs

- Centralized execution may hit a scheduling/GIL/lock limit well before host memory is exhausted → collect queue depth, utilization and capacity curves; reject or publish a bounded recommendation, never assume linear scaling.
- A shared-page scheme can exchange socket copies for allocator and reclamation risk → build it only after bottleneck attribution and count pins/fragmentation as real overhead.
- Local snapshots of remote observations can lag → include scope, incarnation and observation age; refresh asynchronously, never use inspection as readiness authority.
- Shared access makes privileges a group boundary → explicit endpoint capability and security-profile isolation; require application-owned credential configuration, without inspecting or logging secrets.
- The benchmark's single-host single-member replica set may overstate or understate practical benefit → state this scope, expose commands, and make no sharded-cluster or cross-host performance claim.
- Working sets and six-block captures can be expensive to prime → keep the primary workload and targeted sensitivity cases; do not replace full-hot-set priming with a tiny resident subset to improve results.

## Migration Plan

Not applicable after the deferral recorded above. On a positive outcome, add the measured mode as explicit opt-in, with a launch example for the supported worker owner and child-local clients. Roll out to a bounded worker group after local workload measurements. Reverting attachment configuration restores standalone managers; shutting down the owner discards shared entries. A worker close detaches its session and leaves caller-owned clients and other workers running. Stop accepting group work before owner cleanup, and report persistent startup/cleanup errors visibly. Cache content has no migration or durability contract.
