# Design

## Context

See [proposal.md](proposal.md). The same configuration is consumed by local recipes, hooks, hosted jobs, and dependency updaters. File moves need to follow those references together.

## Goals / Non-Goals

Keep validation settings, release pins, and published package behavior intact. Use the tools and invocation mechanisms already in the repository.

## Decisions

### D1. Consolidate configuration in `pyproject.toml`

| Root file     | Destination and compatibility considerations                                                                                                                                                                                                                                        |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.coveragerc` | Use `[tool.coverage.run]` and `[tool.coverage.report]`. Preserve covdefaults, subprocess measurement, omissions, signal handling, and the exclusion regex. [Coverage configuration](https://coverage.readthedocs.io/en/7.16.1/config.html)                                          |
| `mypy.ini`    | Use `[tool.mypy]` with a string Python version and an equivalent verbose exclusion regex. The existing probe runs from a temporary directory and selects the configuration explicitly. [Mypy configuration](https://github.com/python/mypy/blob/v2.4.1/docs/source/config_file.rst) |
| `pytest.ini`  | Use pytest 9's native `[tool.pytest]` table. Preserve marker selection, logging format as interpreted by pytest, strictness, asyncio settings, and test discovery. [Pytest configuration](https://docs.pytest.org/en/9.0.x/reference/customize.html)                                |
| `ruff.toml`   | Use `[tool.ruff]` and its nested tables. Keep the same exclusions for explicit file arguments, lint policy, and formatter settings. [Ruff configuration](https://docs.astral.sh/ruff/configuration/)                                                                                |
| `tox.ini`     | Use native `[tool.tox]`, `[tool.tox.env_run_base]`, and per-environment tables. Preserve runner and packaging selection, inherited settings, argv and substitutions, dependency floors, and environment forwarding. [tox configuration](https://tox.wiki/en/4.67.5/config.html)     |
| `_typos.toml` | Use `[tool.typos]` and its existing subtables with normal discovery. [Pinned typos reference](https://github.com/crate-ci/typos/blob/v1.52.2/docs/reference.md)                                                                                                                     |

Separate files give each tool a smaller configuration file. Consolidation removes six root entries while keeping each tool's namespace distinct. tox also accepts an embedded INI block, which minimizes conversion work but retains INI parsing and hides the settings from TOML tooling. Use native tables and compare resolved configuration during apply.

### D2. Relocate settings selected through existing project commands

| Root file             | Destination                         | Selection and path-sensitive consumers                                                                                                                                                                                                                                                                                                    |
| --------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `.gitlint`            | `development/.gitlint`              | Add `--config development/.gitlint` before the pinned hook's existing `--staged --msg-filename` arguments. Git supplies the message filename. [Pinned hook manifest](https://github.com/jorisroovers/gitlint/blob/v0.19.1/.pre-commit-hooks.yaml)                                                                                         |
| `.secrets.baseline`   | `development/.secrets.baseline`     | Update the detect-secrets hook's existing baseline argument. Carry the tracked baseline intact through the rename.                                                                                                                                                                                                                        |
| `.taplo.toml`         | `development/.taplo.toml`           | Use `--config` for both Taplo hooks and preserve the syntax-only lint configuration. Verify the include/exclude behavior with a repository TOML file and a submodule path. [Taplo configuration](https://taplo.tamasfe.dev/cli/usage/configuration.html)                                                                                  |
| `.vulture_whitelist`  | `development/.vulture_whitelist`    | Update the file list in `[tool.vulture]`, the detect-secrets hook exclusion, and the regeneration command.                                                                                                                                                                                                                                |
| `lychee.toml`         | `development/lychee.toml`           | Pass `--config` with the pinned hook's `--no-progress`. Update the hook exclusion and both CI cache-key expressions. The pinned Lychee still writes `.lycheecache` at the working directory. [Pinned Lychee configuration](https://github.com/lycheeverse/lychee/blob/lychee-v0.24.2/lychee-bin/src/config/mod.rs)                        |
| `sgconfig.yml`        | `development/ast-grep/sgconfig.yml` | Pass `--config` to scan and rule tests, rebase the rule and test directories relative to the config file, and update the rule-test hook trigger. [ast-grep project configuration](https://ast-grep.github.io/reference/sgconfig.html)                                                                                                     |
| `renovate.json5`      | `.github/renovate.json5`            | Use Renovate's built-in GitHub discovery. Update local references, including the Lychee exclusion and tests for configuration changes. [Renovate discovery](https://docs.renovatebot.com/configuration-options/#locations-for-configuration-filenames)                                                                                    |
| `Containerfile`       | `development/Containerfile`         | Update the existing build check's pin reads, tar inputs, and `--file`. Keep the repository-root build context so the version files remain available. Update Dependabot's Docker directory, Renovate's root-anchored Taplo matcher, and CI selection.                                                                                      |
| `docker-compose.yaml` | `development/docker-compose.yaml`   | Update the canonical MongoDB image reader, public and contributor Compose examples, Dependabot's main Compose directory, and CI paths. Use `-f development/docker-compose.yaml --project-directory .` for Docker Compose. For Podman Compose providers without that flag, select the file and pass the checkout's project name with `-p`. |

The root-discovery alternatives leave direct tool invocations shorter. The project already selects these tools through hooks or documented commands, which can own the new paths with their native options. No additional wrapper is needed. The Taplo and ast-grep path checks are covered by task 2.1.

Markdownlint CLI2 reads `development/.markdownlint-cli2.jsonc` via `--config` in both npm formatting scripts. With the pinned release, TOML rule options have a null prototype and Markdownlint's object check drops those options. In particular, it ignores the changelog's `siblings_only` policy. The same settings retain their behavior in the supported JSONC format.

Prettier's `.prettierignore` moves to `development/.prettierignore`. Both npm formatting scripts pass `--ignore-path .gitignore --ignore-path development/.prettierignore` to preserve Git exclusions as well. The pinned Prettier resolves patterns from the ignore file's directory. Use anchored `/../` patterns for paths outside `development/` and paths relative to `development/` for its own entries. A scratch probe confirmed the moved file still excludes the submodule, the verification file, generated paths, and ast-grep snapshots while including an unrelated file with a matching suffix. Update the formatting path selector and the Prettier cache key. The existing npm commands select the shared configuration. [Prettier CLI](https://prettier.io/docs/cli#--ignore-path)

Move `zensical.toml` to `docs/zensical.toml`, set `docs_dir = "user"`, and select it with `-f docs/zensical.toml` in the preview and strict-build recipes. Zensical requires the guide source and output to be inside the configuration directory. A strict scratch build confirmed that the guides and existing snippet paths still render when invoked from the checkout root. In the existing versioned-docs assembler, select the config present at each input revision. Normalize the new config to the assembler's temporary corpus root with `docs_dir = "docs/user"`, so Mike, the snippet base, and redirect generation continue to use the existing corpus layout. Verify a stable tag with the root config and a development ref with the moved config in the same build. Update the CI scope and Pages push filter for the new path. Keep root-relative repository source links pointing to the same files. [Zensical configuration](https://zensical.org/docs/setup/basics/)

### D3. Keep root discovery and project entry points

| Root files                                                                          | Reason                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `.pre-commit-config.yaml`                                                           | Normal Prek hook installation and invocation, hosted CI, and Dependabot's pre-commit manager share the standard root configuration. Passing a custom location would change standard discovery and the dependency-update setup. |
| `.env.example`, `.gitignore`, `.gitmodules`                                         | Keep the environment template beside the conventional local environment, and retain Git's root ignore rules and submodule metadata.                                                                                            |
| `.node-version`, `.python-version`, `rust-toolchain.toml`                           | Keep automatic interpreter and toolchain discovery and the shared selections used by CI, uv, rustup, and the container build.                                                                                                  |
| `package.json`, `package-lock.json`, `pyproject.toml`, `uv.lock`                    | Keep the package manifests and matched lockfiles where npm and uv discover the project.                                                                                                                                        |
| `justfile`, `context7.json`                                                         | Keep recipe discovery and the published Context7 configuration at their project entry points.                                                                                                                                  |
| `AGENTS.md`, `CLAUDE.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `LICENSE`, `README.md` | Keep repository-wide instructions, contribution and release guidance, licensing, and the project overview at their standard entry points.                                                                                      |

### D4. Place project-managed output under `.cache/`

| Local root entry or configured output                                                                           | Disposition                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pytest.log`, `pytest-gw0.log`, `pytest-gw1.log`, `pytest-gw2.log`, `pytest-gw3.log`                            | Put the default and repository-owned alternate pytest log paths under `.cache/pytest/`. Pytest creates the log parent and the existing worker hook derives filenames beside the selected log. Retain lane-specific names and the null-device override. Update CI uploads and the latency-chart recipe's log input.                                                          |
| `site/`                                                                                                         | Use `docs/.cache/site/` for preview and edition output. Set `site_dir = ".cache/site"` in the relocated Zensical configuration and update the existing edition output path and parent creation in the assembler. Update the Pages copy and upload steps. Keep the assembler's staging and backup directories beside its destination for replacement on the same filesystem. |
| `.rust-tools/`                                                                                                  | Install managed Cargo quality tools under `.cache/rust-tools/`. Adjust the existing recipe's install root and PATH, as well as the CI cache path. Cargo's installed binaries and version tracking stay together.                                                                                                                                                            |
| `benchmark-reports/`, `memory-reports/`                                                                         | Neither exists at the root in the inspected checkout. Route repository-owned producers, CI artifact uploads, and current command examples to `.cache/benchmark-reports/` and `.cache/memory-reports/`. Retain historical report references and the legacy ignore patterns so older checkouts' results stay ignored.                                                         |
| `.cache/`, `.hypothesis/`, `.mypy_cache/`, `.pytest_cache/`, `.ruff_cache/`, `.tox/`, `.venv/`, `node_modules/` | Keep established cache and dependency locations with native discovery and existing workflow integrations.                                                                                                                                                                                                                                                                   |
| `.lycheecache`                                                                                                  | Keep the pinned tool's fixed location and existing cache restore/save path.                                                                                                                                                                                                                                                                                                 |
| `.git/`                                                                                                         | Keep Git's private checkout metadata in place.                                                                                                                                                                                                                                                                                                                              |

Using project-local cache paths keeps CI artifact collection and contributor commands checkout-relative. OS temporary paths simplify disposal for individual processes but do not fit outputs read by later commands. Shared user-level caches would mix results across checkouts. Tool-owned cache defaults remain useful even when a path override exists. No tool upgrade is needed for this design.

## Risks / Trade-offs

- A moved pathname can silently stop selecting a check, restoring a cache, or running an uploader. Exercise the current path-based tests and account for CI consumers and dependency bots in the same changeset as each move.
- Explicit Prek arguments override hook-manifest defaults. Preserve the relevant inherited arguments when adding configuration paths.
- A historical artifact can occupy a new destination or contain the only copy of an investigation. Move local entries without overwriting, or leave a collision in place and report it. Clean builds can replace the generated site, so preserve the existing site separately if it contains evidence worth retaining.

## Migration Plan

Land each tracked move with its callers. In the checkout used for apply, account for the inventoried local entries before running commands that write new results. Preserve existing contents with reversible moves and keep legacy ignores where old paths can still contain local data. Other checkouts can continue to read existing outputs in place while new runs use the configured paths.
