# Proposal

## Why

Two mechanically distinct kinds of dead weight have accumulated in `src/`: public `CacheCore` methods exercised only by unit tests (never by the synchronous/asynchronous facades or any other production path), and conditional branches guarding for value shapes that real MongoDB/pymongo data never produces, exercised only because a unit test constructs a contrived value. Confirmed example of the first kind: `CacheCore.lifecycle_state` and `CacheCore.lookup_by_alias` in `src/client_query_cache/_core/manager.py` have zero references outside `tests/core/`, `tests/asynchronous/`, and `tests/synchronous/` (all `pytest.mark.unit`); production code resolves aliases via the separate `resolve_alias` + `lookup_identity` pair instead. Candidate of the second kind, still to be dynamically verified: `interpret_list_collections_entry` in `src/client_query_cache/_core/collection_metadata.py` treats a `listCollections` entry whose `type` is outside `{"collection", "view", "timeseries"}` as "not cacheable," which may never actually occur for this project's supported MongoDB versions. A branch that looks like this kind but is not — `_wall_time_seconds`'s `tzinfo` guard in `src/client_query_cache/_core/stream_events.py` — turned out to depend on the caller's `CodecOptions.tz_aware` setting rather than on anything MongoDB itself can vary; design.md records it as a worked counter-example of why suite-passing alone is not sufficient proof. Both dead-weight patterns bloat the code that humans and coding agents must read, and a genuine shape guard invites false assumptions about what MongoDB can actually return; a guard that is not actually dead must stay.

## What Changes

- Run `coverage run -m pytest -m 'not unit'` against a real MongoDB (via `testcontainers`) and read `coverage report -m --include 'src/*'`; a `src/` symbol it reports as `Missing` is a _candidate_ the non-unit suites don't reach — not yet proof it is reached only by unit tests, since a real production path can simply lack non-unit coverage today. Confirm each candidate has no production (`src/`) call site before deleting it, then delete confirmed dead symbols (starting with the two found above) and update or remove the unit tests that exclusively exercised them.
- Audit conditionals in `src/` that guard on the shape or type of a value sourced from MongoDB, pymongo, or bson (change-stream events, driver return values, BSON-decoded documents) to determine whether the guarded alternate branch is reachable with real data, by temporarily disabling the guard and rerunning the non-unit suites, _and_ checking whether the guarded value depends on a caller-configurable `CodecOptions` setting — suite-passing alone is not sufficient, as `_wall_time_seconds`'s `tz_aware`-dependent branch showed during planning.
- For each branch confirmed always-true (or always-false) against real data with no caller-configurable dependency: delete the dead alternate branch outright, with no replacement guard, assertion, or comment; delete unit tests that only existed to hit the removed branch.
- Convert `mapping.get(key, default)` calls on driver-sourced mappings to `mapping[key]` guarded by `try`/`except KeyError` where the key is expected to almost always be present, keeping the conversion permanently and using an always-uncovered `except` branch under the non-unit suites as the dead-fallback proof.
- Where a removed branch's condition was hiding a real, currently-unhandled input class (rather than being provably unreachable), leave the code unchanged and record the finding instead of deleting it.
- Where a branch is confirmed real but the non-unit suites do not exercise its actual caller configuration (`_wall_time_seconds`'s `tz_aware` dependency and `without_id`'s custom-decoder dependency), add an integration/e2e test that configures that setting for real. The baseline already covers `_wall_time_seconds`'s aware branch through manually constructed datetime values, while `without_id`'s decoder branch is a line-coverage gap. Measure non-unit `src/` coverage again and record the remaining gaps. Reaching >95% requires controlled driver failures and lifecycle races, so that target belongs to follow-up work.

## Capabilities

No specification delta: this removes internal dead code and proven-always-true/always-false branches, with no change to any documented library behavior, public API, or runtime cache semantics.

## Impact

- Affected files: `src/client_query_cache/_core/manager.py` (`lifecycle_state`, `lookup_by_alias`), `src/client_query_cache/_core/collection_metadata.py` (`interpret_list_collections_entry`), `src/client_query_cache/_core/unique_keys.py` (`_is_eligible_index`/`discover_unique_keys`), and any other `src/` module where the coverage report confirms a test-only symbol with no production caller. `src/client_query_cache/_core/stream_events.py` and `src/client_query_cache/_core/projection.py` are explicitly out of scope — design.md's audit inventory found both guard a caller-configurable `CodecOptions` setting, not an impossible MongoDB shape.
- Corresponding unit tests in `tests/core/`, `tests/asynchronous/`, and `tests/synchronous/` that exist only to exercise removed code.
- New integration tests in `tests/synchronous/test_streams_integration.py`, `tests/asynchronous/test_streams_integration.py`, `tests/synchronous/test_collection.py`, and `tests/asynchronous/test_collection.py` covering the `tz_aware` and custom-`CodecOptions` cases found above.
- No public API, dependency, or runtime behavior changes for callers who only exercise real MongoDB-backed paths.
