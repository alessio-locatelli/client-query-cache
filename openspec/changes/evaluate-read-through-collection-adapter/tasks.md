# Tasks

This study modifies no runtime behavior and declares `skip_specs: true`. Execute experiments only under `/tmp` against disposable development fixtures, using read-only imports of the working tree. Retain reproducible sources, commands, matrix evidence, and concise measurements in `docs/development/research/read-through-collection-adapter-evaluation.md`; raw outputs remain untracked. Production implementation is a separate change. Design D1-D7 define coverage and completion; consumer samples and unsuccessful prototypes cannot establish full compatibility or infeasibility.

Record source URLs/revisions and Python/MongoDB versions/topologies in the report. - [ ] 1.2 Expand each method into D1's argument partitions: positional/keyword forms, defaults/omission/`None`, variadic options, valid boundaries, malformed input, and interacting options affecting validation, results, side effects, cache identity, or eligibility. Document source-based reasoning for each partition and shared delegation path, including new/unknown options. Verify every inventoried parameter and semantic interaction maps to a matrix row and an experiment or exact native-delegation argument; record gaps as unverified rather than assuming sampled or pairwise calls prove coverage.
- [ ] 1.3 Create reusable differential experiment functions and checks in `/tmp` using the existing disposable MongoDB fixture mechanisms. - [ ] 2.2 Investigate `find_one` partitions against raw PyMongo, including scalar-ID/mapping inputs, projections, sort, effective collation, decoding, sessions, and additional driver options. - [ ] 2.3 Investigate `count_documents`, `estimated_document_count`, and `distinct` partitions, including option interactions and arguments discovered in 1.2. ## 3. Cursor-returning find investigation

- [ ] 3.1 Build real sync/async `find` cursor prototypes with native construction timing, immediate yielding on misses, a compatible hit-cursor path, and original generation capture before native execution. Snapshot candidate data before yielding and publish only complete results passing the original guards. Retain decisive runnable sources and traces in the report; verify ordinary, empty, limited, and projected results, caller mutation isolation, and no changes to iteration or awaiting when replacing the adapter with raw PyMongo.
- [ ] 3.2 Exercise every public cursor operation from 1.1 and its argument interactions, including sort/skip/limit/projection/collation, batch size, `to_list`, indexing/slicing, clone, rewind, explain, close, and context cleanup where native contracts provide them. Finalize output-affecting query state before lookup and prevent chained methods from silently escaping cache interception. Record outcomes and reproductions; verify miss/hit/disabled behavior and errors match each versioned contract and modified cursors cannot reuse an incompatible cache key.
- [ ] 3.3 Exercise early break, abandonment/garbage collection, timeout, iteration failure, cancellation, concurrent writes, continuity loss/recovery, manager closure, and disabling caching before execution or during consumption. Retain concise traces and reproduction sources. Verify incomplete, mutated, invalidated, or disabled candidates are not published, no disabled execution serves cache entries, and candidate/native resources follow the declared cleanup and ownership contracts.
- [ ] 3.4 Prototype per-entry and shared active-cursor candidate-buffer limits with small/large streams, oversized single documents, and multiple active/abandoned cursors. Discard candidate data when either limit is crossed while continuing native result delivery. Record the design, runnable sources, and allocation observations; verify results remain complete, retained candidates obey the declared limits, and encoded-byte bounds are not reported as process-memory bounds.
