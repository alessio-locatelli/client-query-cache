# Shared worker cache: native byte relay

This study continues [issue #272](https://github.com/alessio-locatelli/client-query-cache/issues/272) after [version 12 misses the eight-worker cold bounds](../v12/results.md). The single `shared-index` candidate is the first clean commit containing this registration and the complete implementation below. Record its revision in every report; later implementation changes invalidate acceptance measurements.

## Candidate and observer

Retain v12's admission fences and extend its allocation reduction: each namespace reuses one guarded lock context, including interrupted-acquisition cleanup. Exact dictionaries and scalar equality values avoid generic mapping checks. Plain signed 64-bit integer wire keys reuse a fixed BSON envelope generated by the official encoder; differential tests preserve exact bytes and decoded types, and damaged envelopes remain protocol errors. Other representations use the existing parser.

The shared-cache harness forwards relay bytes in the existing native extension, with the Python GIL released for the connection's lifetime. One native return-direction thread and the calling connection thread run blocking I/O with a fixed 64 KiB buffer per direction. Successful writes update atomic byte counters. Partial writes drain before the next read, preserving backpressure; EOF shuts down only that direction after pending bytes are sent, so the peer may still reply.

Pause and resume use one condition-variable gate shared by the proxy's connections. Stop wakes paused senders before Python shuts down sockets. Severing the original sockets also shuts down their native duplicates. Native forwarding owns duplicated descriptors before releasing the GIL, preventing Python teardown from invalidating a descriptor in use. Setup failures remain visible. Keep TCP_NODELAY on both legs, every direct-path byte oracle and all existing fault controls. The base byte proxy remains available for other stream-cost workloads.

The [environment](environment.json) freezes the relay model and rebuilt native binary digest. This changes the measurement observer on every path, including direct and independent baselines. Historical studies remain frozen. [Development diagnostics](development.md) motivate the correction and are excluded from acceptance.

## Frozen protocol

The [configuration](config.json) differs from v12 only in registration number. Run fresh thirty-eight-window baseline-only qualification before candidate timing, starting at 1,006/1,000/319 requests/s. Retain v10's downward-only halving rule, three-attempt cap, sample-preserving durations, all health requirements and both manual checks. No candidate observation selects a rate.

Run the complete twelve-block cold phase first. Any failed or unstable required bound stops the study. A pass still requires fresh screening (six blocks), confirmation (twelve), capacity (three windows at every required point), active (twelve), sensitivity (three), and all seventy-five timed faults. Preserve every v9 inference setting, sample floor, balanced order, seed, draw count and leave-one-out check. Report sorted-find sensitivity separately; it cannot support general promotion.

Issue #272 requires cold P95 and P99 upper bounds no more than 1 ms above direct reads at four and eight workers in both execution models, with passing hot, active, capacity and timed-fault evidence. No historical phase substitutes for this candidate's evidence. Budget approximately eleven hours for qualification and performance acquisition, plus smoke, timed faults and analysis.
